# Optional desktop extensions

Select a trusted build-time extension with `OPENCODE_DESKTOP_EXTENSION=/Users/guochunzhong/git/oss/opencode/packages/desktop-tab`. Omit it, or set it to `none`, to build the base desktop. This is a distribution composition seam, not a runtime marketplace or an untrusted plugin loader.

The checkout supplies a `desktop-extension.json` manifest with `apiVersion: 1`, `main`, `preload`, `renderer`, `preloads` (entry name to source path), and `assets` (output-relative path to source path). All source paths are relative to the manifest directory. Renderer files are served during development and copied into `out/renderer` during builds; directory assets are copied for builds and can use their own development server. Electron's packager consumes only the resulting output.

The public type-only API is exported as `@opencode/desktop/extension` from `src/extension.ts`. The main module exports a `DesktopExtension`; the renderer module exports a `DesktopRendererExtension`; the preload module installs the extension's own limited bridge.

The optional `environment` hook runs after loading the user's shell environment and receives the resolved desktop resources directory. Distributions own their config-directory defaults through this hook. The host calls initialization after the desktop environment and Electron are ready, before service discovery. Optional service CORS contributions apply only during initial service discovery.

A window extension returns its primary content, active content accessor, optional native content root, disposal, and optional permanent-close cleanup. `createRenderer` records the extension's HTML and development URL; the returned primary renderer loads after the host installs window readiness listeners, regardless of its ID. Other renderers load automatically. Native browser panes use the returned content root so their bounds and visibility follow the primary tab. The host continues to own recovery, native window controls, main-renderer IPC, state storage, and shutdown. Window state is retained during application quit.

The optional `beforeQuit` hook runs for the renderer's explicit quit request and can await the host's `stopService()` callback. Desktop Tab uses it for the account dialog's exit action so the next launch starts the service with the saved credentials. The base desktop leaves its background service running. Normal application quit retains its existing lifecycle and does not invoke this hook.

Extensions create trusted bundled renderers through `createRenderer`; only these receive the normal desktop RPC bridge. External contents use `trackContents` for window ownership without receiving that bridge. Extension IPC handlers are registered and disposed centrally by `src/main/ipc.ts`. Extensions must validate their own sender, frame, origin, and payload boundaries; registration does not grant every renderer access.

Initialization can carry extension-owned fields while the normal sidecar boundary still omits the Basic credential. The legacy `AppGetCybrosCurrentUser` RPC is a compatibility forwarder for existing 7777 builds; its implementation lives in the optional extension. The generic account dialog and navigation/menu surfaces remain host-owned.

The SigmaAgents implementation is maintained in the separate sibling checkout `packages/desktop-tab`. See that repository's README for configuration and distribution commands. Generic navigation/history menus, trusted-renderer ownership, recovery, native appearance, CLI CORS configuration, and reconnect behavior remain in their owning packages. The legacy account RPC is retained only for wire compatibility. Pre-existing THAPE branding/resource packaging and the desktop's core SSO bootstrap remain outside this extraction; the bootstrap supplies provider environment values before service discovery and also serves CLI consumers.
